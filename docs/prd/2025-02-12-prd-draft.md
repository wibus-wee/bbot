# PRD — Agent Runtime Platform (MVP)

## 1. 产品定位（一句话）

构建一个**长期运行、可持久记忆、可真实执行任务的 AI Agent 工作平台**，通过 Telegram / Web / TUI 多入口驱动，由 Core Daemon 统一管理。

我想要的，就是，我在 Telegram 能连上 OpenAI Codex，然后，我能在 telegram 里面开发我们这个项目，实现自举。

---

## 2. 问题陈述

当前 AI 产品存在的问题：

1. 会话是临时的，不可持续
2. 多界面割裂（聊天是聊天，代码是代码）
3. 无法长期记住上下文与项目状态
4. 无法成为“开发与工作的中枢”
5. 我想要聊天 也想要执行任务，但是现在只能二选一，甚至我没法用来聊天

我们要解决的问题：

> 如何让 AI Agent 成为一个长期运行、具备真实执行能力、可跨界面使用的统一工作中枢？

---

## 3. 产品目标（MVP）

MVP 目标不是“多模型”“多用户”“云平台”。

MVP 目标是：

1. 单用户
2. 本地 Core Daemon
3. 基于 pi-mono 的 Agent Runtime
4. Telegram 作为首个入口
5. 可持久 Demo Session
6. 可执行真实任务（写文件、运行命令、部署）
7. 数据持久化（Drizzle + DB）

---

## 4. 核心能力

### 4.1 Agent 持久运行

* Agent 不再是一次性对话
* 每个 Demo Session 都有持续存在的状态
* Agent session 与 Demo Session 分离

---

### 4.2 统一 Core Daemon

Core 负责：

* Session 管理
* Run 调度
* 工具执行
* 数据持久化
* 事件流（logs / progress）
* 资源控制

Core 是唯一真相源。

---

### 4.3 多入口支持

MVP 支持：

* Telegram Bot
* HTTP API
* Web UI（基础）
* TUI（基础）

所有入口：

* 不直接操作数据库
* 不直接调用 Agent
* 只调用 Core API

---

### 4.4 执行原语（Tools）

Agent 只能通过 Core 调用最小、确定性的 Tool 原语：

* read
* write
* edit
* search
* bash

CLI 只是 `bash` 的执行载体，不单独抽象成能力。
Tool 由 Core 实现并执行，Agent 仅发起调用。
所有 Tool 调用的输入/输出进入 Run 日志，保证可审计与可重放。

---

### 4.5 Skills

Skills 是由 Tools 组合而成的工作流（例如 build / preview / deploy）。
每个 Skill 是一个目录，入口文件为 `SKILL.md`，可选包含 `scripts/`、`templates/`、`references/`。

落盘与边界：

* 内置 Skills（受信任，随版本发布）：`packages/agent/skills`
* 项目级 Skills（外部扩展，默认受限）：`./.agents/skills`
* 用户级 Skills（外部扩展，默认受限）：`~/.agents/skills`

Core 负责 Skills 的发现、加载、校验与权限边界控制。
外部 Skills 必须通过 allowlist 或权限声明后才能调用敏感 Tools（如 `bash`）。

---

## 5. 系统架构

```
Transport (Telegram / Web / TUI)
        ↓
SDK
        ↓
Core Daemon
        ↓
Agent Runtime (pi-mono)
        ↓
Skills (playbooks)
        ↓
Tools (read / write / edit / search / bash)
        ↓
Runner / CLI
        ↓
Database (Drizzle)
```

---

## 6. 技术架构（MVP）

| 层          | 技术                              |
| ---------- | ------------------------------- |
| Monorepo   | pnpm + Turborepo                |
| Backend    | Node.js                         |
| Agent      | pi-mono (`@mariozechner/pi-ai`) |
| DB         | PostgreSQL                      |
| ORM        | Drizzle                         |
| Validation | zod                             |
| Bot        | grammY                          |
| Queue      | p-queue                         |
| Testing    | Cucumber + Vitest               |

---

## 7. 会话模型

双层会话模型：

| 层               | 作用      |
| --------------- | ------- |
| Demo Session    | 产品层工作空间 |
| pi-mono Session | 推理上下文   |

Core 管理 Demo Session。
Agent 管理 reasoning history。

---

## 8. 用户流程（MVP）

### 创建会话

用户：

> /new

系统：

* 创建 WorkspaceSession
* 持久化
* 绑定 Telegram Topic（如有）

---

### 执行任务

用户：

> 帮我创建一个 Fastify 服务

系统：

* Core 创建 Run
* 调用 Agent
* Agent 使用文件工具写入文件
* 记录 Run 状态
* 推送日志

---

### 部署

用户：

> deploy

系统：

* 调用 runner
* 启动服务
* 建立 preview URL
* 更新 WorkspaceSession.previewUrl

---

## 9. 非目标（MVP 不做）

* 多用户系统
* 权限体系
* 云托管
* 分布式执行
* 插件市场
* 多 Agent Provider 抽象

---

## 10. 成功指标

MVP 成功意味着：

1. 能持续使用一个 WorkspaceSession 多轮执行任务
2. 能真正写文件、跑程序、部署
3. 能在 Telegram 之外继续控制
4. 数据重启后不丢失
5. BDD 能覆盖核心流程

---
